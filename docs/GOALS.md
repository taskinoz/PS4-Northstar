# Northstar PS4 feature-completeness goals

Updated 2026-10-01. **This is the current tracker for every agent.** Earlier tracker states are in [GOALS-HISTORY-2026-09-17.md](GOALS-HISTORY-2026-09-17.md) and [GOALS-HISTORY-2026-09-27.md](GOALS-HISTORY-2026-09-27.md); they are not current status. Exact native profiles and experiments belong in [TECHNICAL-NOTES.md](TECHNICAL-NOTES.md), which is chronological: a later entry can correct an earlier one.

## Target and baseline

Reproduce PC Northstar's observable behavior with unchanged PC mod sources and the PC profile layout. Implement platform differences in the PS4 runtime/launcher, or as overrides in the `Northstar.PS4` mod. Mount mod archives; never bake scripts into retail VPKs. A native registered under the right name is not implemented until its arguments, return values, state transitions, timing and failures match PC.

Reference: local `tools/NorthstarLauncher-reference`, revision **4df8857814dd683147f1cc5fdae0b3b419a7f1cf**. Paths below are relative to its `primedev/` directory. This is a pinned source audit, not a claim to cover future upstream changes. Review upstream revision changes explicitly. The Northstar mods are pinned to release 1.31.13 (`vendor/NorthstarMods`, `vendor/northstar-release.json`); record metadata versions and content hashes for each integration test.

Authentication uses an **Atlas identity minted on a PC**: by the token helper through the EA app (`token-helper/`, Go, for Windows, macOS and Linux: it signs the game in over the network and renews the token in game), or exported from a signed-in PC Northstar (`scripts/Export-AtlasCredentials.ps1`). Never log tokens or commit identities. Native platform sign-in remains a separate platform task; do not impersonate a successful Atlas response.

Emulator: shadPS4 nightly **`2b5666b3`** is still the documented build. Builds before `ca89b01` crash on every exit from a loaded map. Builds from `c6fa48c7` (#5110) up to the #5133 fix (`f6cd16e8`) draw levels black ([shadPS4#5124](https://github.com/shadps4-emu/shadPS4/issues/5124)). Newer builds with the fix (`4cbd23ef`, prerelease `94e21778`) have run the user's sessions, including remote servers; G25 tracks the longer testing needed before the documented build moves. Check `Run: Revision` in the log first when a crash or rendering fault appears.

Status vocabulary: **Verified** = named acceptance scenario passed with evidence; **Partial** = useful implementation but incomplete behavior or validation; **Adapter** = registered fallback/stub; **Missing** = not implemented; **Investigating** = concrete failure being traced. Emulator and hardware results are separate; nothing here is verified on PS4 hardware.

## Current state (2026-10-03, release v0.2.18-alpha)

Verified on shadPS4 (details and build hashes in TECHNICAL-NOTES):

- Boot to the Northstar lobby with UI, CLIENT and SERVER script VMs; zero script errors in the lobby and in hosted matches.
- Persistence layout is PC 231 plus the console `bm` struct; the lobby and a hosted Kodai match run with it.
- Server browser against the live master server; joining public servers with Atlas `auth_with_server` and the imported uid.
- Hosting private matches; map changes (20/20 harness hops on `ca89b01`, repeated spot checks on `2b5666b3`); leaving a match to the lobby as host and through the server-sent `ns_start_reauth_and_leave_to_lobby` path a remote server uses (tested locally; not yet from a real remote match).
- Private match -> main menu -> multiplayer gives a normal lobby, because `setplaylist` exists natively.
- Custom maps: the `bobthebob.mp_box` map mod (loose PC BSP plus PC VPK) loads with `map mp_box`, renders, spawns the player with zero script errors, and returns to the lobby. A map that no enabled mod or retail archive provides is refused instead of leaving the game stuck.
- Mod localisation follows the PS4 system language with a per-file English fallback; DecodeJSON/EncodeJSON round-trip in all three VMs.
- Controller navigation in the game mode and Host Options menus, with a real pad (2026-09-30).
- Mod auto-download (2026-09-28): verified list fetch, download, SHA-256 check, zip extraction to `/data/northstar_ps4/runtime/remote/mods`, then enable and a live `NSReloadMods`, first through the harness `download` action (`lexi.lexire125` 1.0.7, merged by `weapon_reparse`), then by the user joining a Parkour server through the real browser. The downloaded mod starts disabled at the next boot, as on PC.
- Mod content beyond scripts (details in G08-G13): `Dependencies` constants, custom audio, particle manifests, custom datatable CSVs, compiled `.pdiff` additions, and RPak textures/materials converted with `-ConvertRpaksForPs4` (Northstar.Custom's 47 textures load and its holiday tree renders).
- Thunderstore mods (2026-10-01): two weapon skin packs (converted RPak textures), a weapon sound pack and a HUD script mod with Mod Settings entries; mod `ConCommands`; bans; pad navigation in Mod Settings and the Mods list (details in G08, G12, G13, G22, G23).
- Weapon and font-table KeyValues patches apply (2026-09-28): Northstar.Custom's six weapon patches and the font table. Before this the engine's file cache served those files without reaching the merge, so only the playlist (at boot) and `npc_pilot_elite` (at map load) were merged. A hosted Kodai match plays with all nine.

Known limits:

- Atlas-authenticated host and remote-player persistence uses READY_REMOTE and writes changed data back; insecure fallback remains policy-controlled. Early-leave and Atlas-unreachable failure tests remain.
- Mod RPaks load in normal builds, but only as PS4-layout copies made by the profile tools' `-ConvertRpaksForPs4`; a PC-layout pak copied in by hand is refused at runtime. The converter handles uncompressed v7 texture/material paks and refuses compressed, patch, array and other asset layouts (models, UI images, shaders). Two texture-only Thunderstore skin packs are tested (G12); none of the archived 4K or model-replacing packs are.
- A live reload cannot unload the localisation of mods it disables (the engine's full reload races other threads and was replaced); those tokens stay until the next boot.
- Boot faults fixed (2026-10-01, G25): with the two skin packs installed about half of all boots hung on the Respawn logo or crashed at `0x700000782c41`. The causes were in the runtime (mod localisation and mod paks loaded from its own thread, an unlocked malloc, an unlocked mod scan); 12 of 12 boots reach the lobby after the fixes.
- On crowded, heavily modded servers a 6 GB GPU can run out of memory under shadPS4. shadPS4's GPU caches, not the game's texture budget, fill it; there is no game-side fix.

Work order: G04/G05 need the remaining failure/lifecycle acceptance tests, then the P1 families below. A focused 2026-09-30 survey found no `.pdiff` in 60 active custom-weapon, Titan, loadout, execution and framework packages, so G02's third-party sample is no longer an active priority. Work on an independently testable part when an integration prerequisite is blocked. Do not silence script errors by returning invented defaults or editing the calling PC scripts.

## How an agent works from this tracker

1. Read this file, current uncommitted diff and relevant technical notes before editing. Preserve other agents' work. Pick a goal/subtask and record its current owner/session and evidence below; do not assume a stale note means a missing implementation.
2. Cite the PC source revision and exact behavior. Profile PS4 addresses/layouts read-only first, gate native hooks on module identity/preimages, and preserve rollback. No Windows offsets and no guessed entity/pdata layouts.
3. Document the change and its tests before marking anything Verified. Distinguish source implementation, host tests, startup, local-lobby, remote gameplay, emulator and hardware. A registration count or non-null load handle proves only that event.
4. Use small independently testable changes. Capture the first script failure, callstack and load order before patching downstream symptoms. No fake success values or accumulating script workarounds.
5. Test in the game, not only on the host: [AI.Harness](AI-HARNESS.md) drives launch, console, menus and state queries; `scripts/Send-PadInput.ps1` presses pad buttons; `scripts/Capture-GameWindow.ps1` takes screenshots of the game window.
6. Update this file's handoff row and [TECHNICAL-NOTES.md](TECHNICAL-NOTES.md) with build hashes, log locations, remaining failures and the next concrete test. Keep secrets and extracted retail content out of Git.
