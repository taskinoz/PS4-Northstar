# Northstar PS4 feature-completeness goals

Updated 2026-09-24. **This is the current tracker for every agent.** The chronological notes previously here are preserved in [GOALS-HISTORY-2026-09-17.md](GOALS-HISTORY-2026-09-17.md); they are not current status. Exact native profiles and experiments belong in [TECHNICAL-NOTES.md](TECHNICAL-NOTES.md).

## Target and baseline

Reproduce PC Northstar's observable behavior with unchanged PC mod sources and the PC profile layout. Implement platform differences in the PS4 runtime/launcher. Mount mod archives; never bake scripts into retail VPKs. A native registered under the right name is not implemented until its arguments, return values, state transitions, timing and failures match PC.

Reference: local `tools/NorthstarLauncher-reference`, revision **4df8857814dd683147f1cc5fdae0b3b419a7f1cf**. Paths below are relative to its `primedev/` directory. This is a pinned source audit, not a claim to cover future upstream changes. Review upstream revision changes explicitly. Installed core mod/server versions must also match; record metadata versions and content hashes for each integration test.

The latest user requirement includes the **imported PC Atlas identity workflow**. The earlier blanket “authentication excluded/disabled” instruction in historical notes no longer describes the current goal. Importing a token is a supported development input; token syntax alone does not establish a live session, a server join ticket or downloaded persistence. Never log tokens or commit identities. Native platform sign-in remains a separate platform task; do not impersonate a successful Atlas response.

Status vocabulary: **Verified** = named acceptance scenario passed with evidence; **Partial** = useful implementation but incomplete behavior or validation; **Adapter** = registered fallback/stub; **Missing** = not implemented; **Investigating** = concrete failure being traced. Emulator and hardware results are separate.

## How an agent works from this tracker

1. Read this file, current uncommitted diff and relevant technical notes before editing. Preserve other agents' work. Pick a goal/subtask and record its current owner/session and evidence below; do not assume a stale note means a missing implementation.
2. Cite the PC source revision and exact behavior. Profile PS4 addresses/layouts read-only first, gate native hooks on module identity/preimages, and preserve rollback. No Windows offsets and no guessed entity/pdata layouts.
3. Document the change and its tests before marking anything Verified. Distinguish source implementation, host tests, startup, local-lobby, remote gameplay, emulator and hardware. A registration count or non-null load handle proves only that event.
4. Use small independently testable changes. Capture the first script failure, callstack and load order before patching downstream symptoms. No fake success values or accumulating script workarounds.
5. Update this file's handoff row and [TECHNICAL-NOTES.md](TECHNICAL-NOTES.md) with build hashes, log locations, remaining failures and the next concrete test. Keep secrets and extracted retail content out of Git.
