# Northstar PS4 feature-completeness goals

Updated 2026-09-27. **This is the current tracker for every agent.** Earlier tracker states are in [GOALS-HISTORY-2026-09-17.md](GOALS-HISTORY-2026-09-17.md) and [GOALS-HISTORY-2026-09-27.md](GOALS-HISTORY-2026-09-27.md); they are not current status. Exact native profiles and experiments belong in [TECHNICAL-NOTES.md](TECHNICAL-NOTES.md), which is chronological: a later entry can correct an earlier one.

## Target and baseline

Reproduce PC Northstar's observable behavior with unchanged PC mod sources and the PC profile layout. Implement platform differences in the PS4 runtime/launcher, or as overrides in the `Northstar.PS4` mod. Mount mod archives; never bake scripts into retail VPKs. A native registered under the right name is not implemented until its arguments, return values, state transitions, timing and failures match PC.

Reference: local `tools/NorthstarLauncher-reference`, revision **4df8857814dd683147f1cc5fdae0b3b419a7f1cf**. Paths below are relative to its `primedev/` directory. This is a pinned source audit, not a claim to cover future upstream changes. Review upstream revision changes explicitly. The Northstar mods are pinned to release 1.31.13 (`vendor/NorthstarMods`, `vendor/northstar-release.json`); record metadata versions and content hashes for each integration test.

Authentication uses an **Atlas identity exported from a signed-in PC Northstar** (`scripts/Export-AtlasCredentials.ps1`). Never log tokens or commit identities. Native platform sign-in remains a separate platform task; do not impersonate a successful Atlas response.

Emulator: shadPS4 nightly **`2b5666b3`** is the build to test on. Builds before `ca89b01` crash on every exit from a loaded map; builds from `c6fa48c7` (#5110) on draw levels black (reported as [shadPS4#5124](https://github.com/shadps4-emu/shadPS4/issues/5124)). Check `Run: Revision` in the log first when a crash or rendering fault appears.

Status vocabulary: **Verified** = named acceptance scenario passed with evidence; **Partial** = useful implementation but incomplete behavior or validation; **Adapter** = registered fallback/stub; **Missing** = not implemented; **Investigating** = concrete failure being traced. Emulator and hardware results are separate; nothing here is verified on PS4 hardware.

## Current state (2026-09-27, release v0.2.2-alpha plus later commits)

Verified on shadPS4 (details and build hashes in TECHNICAL-NOTES):

- Boot to the Northstar lobby with UI, CLIENT and SERVER script VMs; zero script errors in the lobby and in hosted matches.
- Persistence layout is PC 231 plus the console `bm` struct; the lobby and a hosted Kodai match run with it.
- Server browser against the live master server; joining public servers with Atlas `auth_with_server` and the imported uid.
- Hosting private matches; map changes (20/20 harness hops on `ca89b01`, repeated spot checks on `2b5666b3`); leaving a match to the lobby as host and through the server-sent `ns_start_reauth_and_leave_to_lobby` path a remote server uses (tested locally; not yet from a real remote match).
- Private match -> main menu -> multiplayer gives a normal lobby, because `setplaylist` exists natively.
- Custom maps: the `bobthebob.mp_box` map mod (loose PC BSP plus PC VPK) loads with `map mp_box`, renders, spawns the player with zero script errors, and returns to the lobby. A map that no enabled mod or retail archive provides is refused instead of leaving the game stuck.
- Mod localisation files load; DecodeJSON/EncodeJSON round-trip in the UI VM.
- Controller navigation in the game mode menu, tested with scripted pad input; a confirming test with a real pad is still wanted.

Known limits:

- Persistence is local only (READY_INSECURE); no remote pdata fetch/write.
- Mod downloads, mod rpaks (the shipped ones are PC builds) and live mod reload are not implemented.
- On crowded, heavily modded servers a 6 GB GPU can run out of memory under shadPS4. shadPS4's GPU caches, not the game's texture budget, fill it; there is no game-side fix.

Work order: G04/G05 (real persistence) and G06 (per-VM helpers, frame queue) are the next P0 gaps, then the P1 families below. Work on an independently testable part when an integration prerequisite is blocked. Do not silence script errors by returning invented defaults or editing the calling PC scripts.

## How an agent works from this tracker

1. Read this file, current uncommitted diff and relevant technical notes before editing. Preserve other agents' work. Pick a goal/subtask and record its current owner/session and evidence below; do not assume a stale note means a missing implementation.
2. Cite the PC source revision and exact behavior. Profile PS4 addresses/layouts read-only first, gate native hooks on module identity/preimages, and preserve rollback. No Windows offsets and no guessed entity/pdata layouts.
3. Document the change and its tests before marking anything Verified. Distinguish source implementation, host tests, startup, local-lobby, remote gameplay, emulator and hardware. A registration count or non-null load handle proves only that event.
4. Use small independently testable changes. Capture the first script failure, callstack and load order before patching downstream symptoms. No fake success values or accumulating script workarounds.
5. Test in the game, not only on the host: [AI.Harness](AI-HARNESS.md) drives launch, console, menus and state queries; `scripts/Send-PadInput.ps1` presses pad buttons; `scripts/Capture-GameWindow.ps1` takes screenshots of the game window.
6. Update this file's handoff row and [TECHNICAL-NOTES.md](TECHNICAL-NOTES.md) with build hashes, log locations, remaining failures and the next concrete test. Keep secrets and extracted retail content out of Git.

## Definition of feature complete

All applicable goals must have acceptance evidence, no required API may remain an adapter, and all unsupported platform-specific PC integrations must have explicit agreed alternatives or exclusions. Imported-token login, local multiplayer-menu entry and one successful match are intermediate milestones. Retail archives and upstream mod sources must remain unchanged, and persistence must survive verified save/load and account/connection lifecycle tests.
